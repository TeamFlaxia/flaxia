# 投稿本文の文字色

投稿本文の一部を固定パレットで着色したり、逆さ文字にしたりできる。
**Flaxia+ 専用**の著者向け機能で、閲覧者側に課金状態は不要。

```
今日は{red}重要{/red}なお知らせです。{blue}青い文字{/blue}も使えます。
```

## 記法

`{スタイル名}本文{/スタイル名}` のペアで囲む。色名は英語または日本語エイリアス。

| 色 | 英語 | 日本語 |
|---|---|---|
| 赤 | `red` | `赤` |
| 橙 | `orange` | `橙` |
| 黄 | `yellow` | `黄` |
| 緑 | `green` | `緑` |
| 青 | `blue` | `青` |
| 紫 | `purple` | `紫` |
| 桃 | `pink` | `桃` |
| 灰 | `gray` / `grey` | `灰` |
| 蜜柑色 | `mikan` | `蜜柑` |
| キムワイプ色 | `kimwaipu` | `キムワイプ` |
| 虹色 | `rainbow` | `虹` |

- `{Dinnerborn}本文{/Dinnerborn}` は本文を 180° 回転して逆さ文字にする
  （`Dinnerbone` / `dinnerbone` も可）。これは色ではなく変形スタイル。
- 任意の HEX / CSS は不可。描画は `post-color--red` などの CSS クラスに限定する。
  `Dinnerborn` は `post-dinnerborn` クラスで描画する。
- 開始と終了の色名が一致しない場合、閉じ忘れ、未知の色名は**記号ごと本文として表示**する。
- `\{red}` のように `{` をバックスラッシュでエスケープすると、色記号ではなく
  `{red}` という文字として表示される。
- 入れ子にできる。ネスト数は投稿の 200 文字制限で自然に制限される。
- コード（インライン / フェンス / インデント）と数式（`$...$` / `$$...$$`）の中では解釈しない。
- 空行、リスト項目、引用、テーブル、水平線、インデントコードをまたぐペアは無効。
  1 つの段落内の改行（`breaks`）はまたげる。

## 権利判定

- サーバーは投稿の作成・編集・返信・引用時に、本文に有効なスタイルペアが含まれるかを
  検査する。
- `badge_type === 'flaxia_plus'`（active / trialing）または reviewer ロールを持つ
  著者だけが色や逆さ文字を付けられる。
- 非加入者がスタイルペアを含む本文を送ると `403`：

```json
{ "error": "flaxia_plus_required", "message": "Text colors require Flaxia+" }
```

- 加入失効後も、**本文を変更しない編集**は許可する。色や逆さ文字を追加・変更するには
  再加入が必要。
- 閲覧者は無料でも色を見られる。
- 引用元の本文は、引用元の著者の現在の Flaxia+ 状態で判定する。

## 保存形式

- v1 では記号を `posts.text` にそのまま保存する。新しいカラムは追加しない。
- 文字数制限（200 文字）には記号も含む。
- 非加入者・加入失効者の投稿では記号を解釈せず、そのまま文字として表示する。
  再加入すると色が戻る（リモート投稿の本文を壊さないための仕様）。
- 本文の Markdown / 投稿参照 / 数式処理と色処理は同じパイプラインで行う。
  色の復元はサニタイズ後の DOM テキストノード上でのみ行い、`href` などの属性には
  注入しない。

## 周辺出力

ActivityPub、OG / SEO、通知プレビュー、埋め込み、ゲームタイトルなどの
プレーンテキスト出力では、有効な色記号を除去する。SSR の投稿本文だけは
Flaxia+ 著者の場合に `<span class="post-color--...">` として描画する。

## UI

色パレット、挿入ボタン、オートコンプリート、プレースホルダー例、tooltip、
`+` メニュー項目は追加しない。Composer は既存の textarea のまま。記法の周知は
ドキュメント、ヘルプ、リリースノート、Flaxia+ 特典説明で行う。

## 既知のトレードオフ

- 検索の SQL `LIKE` は v1 では色記号も検索対象に残る。
- 加入失効中の過去投稿は記号が本文として見える。将来的に `has_color` フラグや
  失効時除去バッチを追加できる。
