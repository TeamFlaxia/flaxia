## 1. 必要なソフトウェア


## 2. Git の使い方

### クローン

```bash
git clone https://github.com/TeamFlaxia/flaxia.git
cd flaxia
```

### ブランチ → main にマージ

現在は PR を必須にせず、**ブランチで作業 → ローカル検証 → main にマージ → push** の運用です。

```bash
git switch -c fix/short-description
# 実装
npm run test:group -- guardrails
npx tsc --noEmit
npx @biomejs/biome ci .
node scripts/check-file-size.mjs
git add -A
git commit -m "fix(area): ..."
git switch main
git pull --ff-only
git merge --no-ff fix/short-description
git push origin main
git branch -d fix/short-description
```

CI と Deploy は `main` への push で走ります。merge commit を残すため `--no-ff` を使っています。

### コミットメッセージ

`type(scope): summary` 形式。

- `feat(composer): ...`
- `fix(feed): ...`
- `refactor(settings): ...`
- `test(shell): ...`
- `docs(architecture): ...`

## 4. プロジェクトのセットアップ

```bash
npm ci
npm run migrate:local
```

環境変数は `.dev.vars` / `.env` に置きます。最低限、Crowd や Stripe を触る場合は該当する secret を設定してください。未設定でもローカルの大半のテストは動きます。

### ローカルテストアカウント

`local-test-accounts.md` を参照してください。

## 5. 開発サーバー

```bash
npm run dev        # Vite + wrangler Pages dev（通常の開発）
npm run dev:hot    # Vite watch + API
npm run dev:local  # フロントエンドのみ
```

統合テストや Durable Object を含む確認では、別ターミナルで以下を起動します。

```bash
npm run dev:do           # NotificationStream (8789)
npm run dev:multiplayer  # Room / Matchmaker (8790)
npm run dev:test         # テスト用 Pages (8788)
```

`dev:test` は `migrate:local` を実行してから `wrangler pages dev dist` を起動します。

## 6. テスト

### ガードレール（サーバー不要）

```bash
npm run test:group -- guardrails
```

アーキテクチャ境界、CSP ハッシュ、lazy import、legacy adapter、Svelte shell、file-size など。

### 機能テスト

```bash
npm run test:group -- posts-feeds
npm run test:group -- auth-vault
npm run test:group -- media-games
```

`posts-feeds` などは `dev:test`（と DO/multiplayer）が必要です。

### 型・Lint・サイズ

```bash
npx tsc --noEmit
npx @biomejs/biome ci .
node scripts/check-file-size.mjs
```

### ブラウザテスト

Playwright は CI で実行されます。

```bash
npm run test:app:browser
npm run test:styles:browser
```

手元に Playwright が無い場合は CI の `render-browser` を確認してください。

### テストの場所

- `tests/*.test.ts` — Node テスト
- `tests/app-shell.browser.mjs` — シェル/画面のブラウザテスト
- `tests/render/` — render engine のテスト
- `packages/flaxia-render/tests/` — render package


## 8. フロントエンドの構成

### SvelteKit SPA

- `src/routes/**/+page.svelte` がルート
- `src/lib/svelte/` が移行済みの画面・部品
- `src/components/` に残る legacy DOM は **`.ts` アダプタ経由でのみ** 呼ぶ
- `LEGACY_ADAPTERS.md` は現在空。増やすことはできません（`tests/legacy-adapters.test.ts`）

### シェル

`ShellLayout.svelte` が 3 カラムを所有します。

```
左ナビ 240–350px / 中央 600px / 右レール 350px
```

- 1200px 未満では右レールを隠す
- 設定・メール・マップ・アーケード・翻訳・通知は右レールなし
- モバイルは左ナビがドロワー、下部タブバー

### ナビゲーション

```ts
import { navigate, navigateReplace } from '../lib/navigation.ts';
await navigate('/home');
```

`history.pushState` は使いません（SvelteKit の `history.state` を壊すため）。

### Svelte 5

```svelte
<script lang="ts">
  let count = $state(0);
  const doubled = $derived(count * 2);
</script>
```

`$derived` は **値** です。`doubled()` のように呼ばないでください。

### アップロード

- 無料: 25MB/ファイル、50MB/投稿
- Flaxia+: 128MB/ファイル、256MB/投稿
- 25MB 超は `src/lib/upload.ts` が 16MB ずつに分割し、`/api/upload/...` の `part` / `finalize` で結合
- サーバー側の上限・所有権・スキャンが authoritative

### CSS

- `src/styles/index.css` が入口
- legacy / redesign / overrides の順で読み込み
- **`@layer` は使いません**（`index.html` の unlayered critical CSS が勝ってしまうため）
- Tailwind v4 は依存として入っていますが、`src/app.css` は未 import（token のミラーのみ）。採用する場合は layer 移行の設計が必要

## 9. バックエンドと Ports

### API

`functions/api/[[route]].ts` が Hono ルーターをマウントし、機能別の `functions/api/routes/*.ts` に委譲します。

### Ports / Adapters

機能コードは `functions/lib/ports/` の型だけに依存します。

- `Db`
- `Kv`
- `BlobStore`
- `Queue`
- `Realtime`
- `Vector`
- `Tasks`

Cloudflare 依存は `functions/lib/adapters/cloudflare/` に閉じ込めます。
新しい `c.env` 参照や `D1Database` / `R2Bucket` を adapter 外に足すと `tests/architecture.test.ts` が落ちます。

### 共有契約

`shared/` に型・SRP・メールアドレス・アップロード上限・ZIP 定数などを置きます。
`functions/**` から `src/**` を直接 import してはいけません。

## 10. よくあるエラー

| エラー | 対処 |
|---|---|
| `biome check` が失敗 | `npx @biomejs/biome check --write <files>` |
| `tsc --noEmit` が失敗 | 型・import パスを確認。Svelte は `$derived` の扱いに注意 |
| `wrangler` の認証エラー | `npx wrangler login` |
| D1 のテーブルが無い | `npm run migrate:local` |
| 統合テストが `fetch failed` | `dev:do` / `dev:multiplayer` / `dev:test` が起動しているか確認 |
| `file-size` が失敗 | 500 行超のファイルを分割するか、意図した成長なら baseline を更新 |
| CSP でインラインスクリプトがブロック | `npm run build` でハッシュを再生成 |
| `wrangler` が types 古いと警告 | `npx wrangler types` で `worker-configuration.d.ts` を再生成 |
